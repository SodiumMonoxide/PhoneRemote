# 从源码构建

构建脚本在 Windows PowerShell 5.1 或 PowerShell 7 上运行。依赖需预先安装，仓库不附带 SDK/JDK。以下命令从仓库根目录执行。

## Windows

需要 Windows x64 和 Microsoft .NET 10 SDK。本次发行使用 SDK 10.0.404、运行时 10.0.15。`scripts/build-windows.ps1` 将运行时固定为 10.0.15，与随附第三方声明对应。

```powershell
.\scripts\build-windows.ps1
```

如 SDK 未加入 PATH，可传入 `-DotNet` 指定 `dotnet.exe`。输出在 `artifacts/windows`，含 `PhoneRemote.exe`、指南和运行时许可。完整打包该目录即可分发，目标电脑无需另装 .NET。

只编译源代码时：

```powershell
dotnet build .\windows\RemoteControl.csproj -c Release
```

## Android

需要 JDK 21、Android SDK Platform 35 和 Android SDK Build-Tools 35.0.1。用官方 SDK Manager 安装对应组件，设置 `JAVA_HOME` 与 `ANDROID_HOME`。

```powershell
.\android\build.ps1
```

默认输出 `artifacts/PhoneRemote-v2.3.0-Android-unsigned.apk`。**未签名包不能直接安装**，用于检查源码构建；脚本不会生成签名密钥。

可以显式传入 `-JavaHome`、`-AndroidSdk`、`-BuildToolsVersion`、`-PlatformVersion`。工具链采用非标准目录时，可使用 `-BuildToolsPath` 和 `-PlatformJar` 指定 Build-Tools 目录及 `android.jar`。

页面从 `windows/Web` 重新内联到 APK，并计算与内容匹配的 CSP SHA-256。Java 代码编译为 API 29 起可用的 DEX。每次使用独立的 `.build/android` 子目录，避免混入旧文件。

## Android 发布签名

把自己的签名库和密码文件放在仓库外。构建时同时传入：

```powershell
.\android\build.ps1 `
  -KeystorePath $env:PHONEREMOTE_KEYSTORE `
  -StorePasswordFile $env:PHONEREMOTE_STORE_PASSWORD_FILE `
  -KeyAlias $env:PHONEREMOTE_KEY_ALIAS
```

环境变量内容分别为外部签名库路径、外部密码文件路径和密钥别名。若私钥密码与签名库密码不同，另传 `-KeyPasswordFile`。脚本以密码文件方式调用签名工具，不把密码作为命令行明文参数。签名后运行 `apksigner verify` 和 `zipalign` 校验，输出 `artifacts/PhoneRemote-v2.3.0-Android.apk`。

**升级必须继续使用同一签名密钥。** 此仓库不提供正式发行签名私钥。自己构建并用不同密钥签名的 APK 无法覆盖安装已有发行版，卸载会移除应用数据，因此不要为试构建而卸载正在使用的应用。

## 发布前检查

- 同时核对 Windows 版本与 Android Manifest 的版本号、versionCode。
- 使用全新目录构建，验证两种模式首次配对、保存重连和主动切换。
- 验证窗口后台运行、托盘恢复、完全退出与重新启动行为。
- Windows 包包含所用运行时的许可证和第三方声明。
- 源码包只包含受版本控制的文件，避免打包 `.build`、`artifacts`、签名材料和用户数据。
- 对分发包生成 SHA-256 并与下载产物核对。不要将私钥、设备配对或真实连接截图放入 Release。

官方工具下载：[.NET](https://dotnet.microsoft.com/download/dotnet/10.0)、[Microsoft OpenJDK](https://learn.microsoft.com/java/openjdk/download)、[Android SDK Manager](https://developer.android.com/tools/sdkmanager)。
