# Windows 虚拟机验证

验证日期：2026-11-19。适用版本：Windows 2.5.0。

使用一台 Windows 宿主机作为控制端、Windows 沙盒作为被控端，通过虚拟网络连接生产版 HTTPS 服务。控制端沿用生产界面和输入处理，只把配对存储位置指定为独立测试目录。沙盒使用临时身份，未导入已有手机、局域网或 Tailscale 配对。

## 已完成的界面实测

| 项目 | 结果与依据 |
| --- | --- |
| 配对与画面 | 控制端连接独立被控端，显示实际桌面并进入全屏。 |
| 鼠标 | 被控端检测到左键单击、双击、右键、滚轮和拖动；计数为左键 2、双击 1、右键 1、滚轮累计 -480、拖动 1。拖动结束后目标位置改变，按住状态已结束。 |
| 退出键鼠与全屏 | 从顶部工具栏退出键鼠控制，恢复普通窗口，连接和画面保留，输入处于暂停状态。再次点击暂停的远程画面未产生遥控输入。 |
| 本机文本粘贴 | 从本机剪贴板读取、预览并发送合成测试文本，包含英文、中文、emoji、Tab 和 CRLF 换行；692 个 UTF-16 单元分三段到达被控文本框，长度及 UTF-8 SHA-256 与预期一致。 |
| 粘贴后状态 | 重新读取预览和关闭预览未重复发送文本，键鼠控制保持暂停。 |

合成测试文本的 SHA-256 为 `a8ad61ca64ea63001c6bdc58149c695684103cbc9f1d4534eb37ac02185f4242`。该值用于核对测试文本，不是设备身份、证书指纹或配对凭据。宿主机与沙盒之间禁用了剪贴板重定向，因此粘贴结果来自 PhoneRemote 的文本发送功能。

## 通过输入接口的键盘实测

另用已配对的测试客户端向生产 HTTPS 输入接口发送按下和松开请求，并在沙盒内检查真实文本框及输入探针。以下检查验证了网络输入协议到被控端 Windows 输入的链路；它们没有经过主控端实体键盘捕获钩子。

- Ctrl+A 能选中已有文本；英文模式下，普通字母数字及 Shift 大写组合得到预期内容。
- Shift+Left 能扩展选区，松开 Shift 后继续编辑正常。
- 同一按键的重复按下能产生重复字符。
- 按住 Shift 后发送 `releaseAll`，后续数字输入正常；按住 Ctrl 时断开并重新连接，后续输入也正常，未出现修饰键残留。

## 被控端输入法

直接键盘控制传递按键代码，文字结果由被控端的键盘布局和输入法决定。本次测试中，被控端处于中文输入模式时，`abc123` 被输入法解释为中文候选并产生「按不出」，不能据此判定按键丢失。检查英文按键时，应先将被控端输入法从「中」切换为「英」。需要准确发送中文、emoji 或多行内容时，可使用预览确认后的本机文本粘贴功能。

## 配套回归检查

本次运行 `client-ui` 75 项、`keyboard-capture` 78 项、`input` 41 项、`input-wire` 15 项，全部通过。它们分别检查窗口与文本流程、键盘路由、输入释放和 HTTPS 输入传输。测试使用事件或输入后端替身，不把模拟通过当作实体键盘实测通过。执行方式见[回归检查](../tests/README.md)。

## 仍待验证

- 主控端实体键盘经过真实全局钩子到被控端的完整链路，以及真实按下 Ctrl+Alt+F12、Ctrl+Alt+Enter 的行为。本次无人提供实体键盘输入；自动化生成的键盘事件会被生产过滤逻辑忽略，测试未关闭该过滤。
- 两台实体 Windows 电脑、不同 DPI 和键盘布局，以及真实网络延迟下的操作表现。
- 双 Windows 通过 Tailscale 跨 Wi-Fi 的连接与遥控；沙盒虚拟网络结果不能代表该场景。
